# 学习画像引导 P0/P1 实施说明

实施范围以对话中确认的 P0/P1 为准。原计划的 P2 自动补全、设置页编辑与完整历史迁移暂不实施。

## 用户流程

1. 学习背景：身份必选；学段或职业补充选填；学科可以多选或输入补充。
2. 基础与目标：自评基础选填；目标类别必选；具体描述和目标日期选填。
3. 学习方式：困难、形式偏好、单次时长和多个时段均可留空，也可跳过本页。
4. 摘要确认：允许返回修改，再统一校验文字并提交。

任何一屏都可选择“稍后完善”。这会结束本次引导，不提交尚未确认的表单草稿，已有画像仍保留。
完成或跳过后进入 /home；已经有引导完成时间的老用户不会被重新要求填写。
正常提交的身份、学科、目标在前后端均检查。若补充学科是无效文字，不阻塞结束引导，但对应维度保持待补充。

## 数据和状态

- 仍使用 LearningProfile.dimensions JSON，无需数据库结构迁移。
- 七项展示为：身份与学段、学科与领域、现有基础、学习目标、薄弱与困难、内容形式偏好、可用时间。
- 新增 identity、learningGoals.kind/targetDate、knowledgeBase.details/selfAssessed、onboarding 元数据。
- 学科映射 knowledgeBase.subjects；形式偏好映射 interests.preferredFormats；时段映射 timePreference.preferredTimeSlot。
- 保留旧认知风格、节奏、错误模式和兴趣数据，不在引导里采集，不由默认值推测身份或基础。
- 完整度只计算已确认的身份、学科和目标；不等同于学习能力或掌握度。
- 采集状态：已确认、待确认、待补充、已跳过。文本状态单独记录，选择有效而文字无效时不丢弃选择。
- 无效及待确认原文不进入画像、长期记忆或服务端草稿；页面内输入在刷新前可重试。
- /profile 改为真实七项画像展示，移除原先的模拟学习统计。
- 路径接口优先读取当前登录用户的服务端画像；后续节点规划不读取长期记忆。
- 目标日期作为画像上下文使用，本期不自动拆分每日任务或重排已生成路径。

## 提交与记忆

新增 POST /api/v1/profile/onboarding：
- 身份从服务器认证获得，不接受请求体 userId。
- 选择值和日期通过白名单、日期真实性、长度与必填校验。
- 有文字时，统一进行一次模型抽取及分类；只保存明确有效的客观学习事实。
- 无文字、整份跳过、显式放弃文字时不调用模型。
- 提取失败返回可重试状态，不更新画像或完成标记；用户可明确选择仅保存选择项。
- 用户记录完成时间与画像写入同一数据库事务，使用用户级锁串行处理。
- 同一已保存的 submissionId 重试不重复写入或增加版本；相同标识但内容变化返回冲突。
- Next.js after 在响应之后同步记忆；失败只记录不含原文的日志，不回滚画像。
- 记忆重新读取最新已提交画像，L1 保留事实变更历史，L2/onboarding 与 L3/profile 中的问卷段落保存当前有效事实副本。
- 问卷摘要直接由已校验结构化信息生成，无需额外模型调用；重复同步不追加相同记忆。
- 记忆副本仅用于对话上下文，不反向覆盖画像，不参与完成度计算或路径输入。
- 异步记忆失败目前可通过同一提交重试恢复，尚未引入持久化重试队列。

## 验证与后续边界

关键逻辑测试位于 lib/onboarding/__tests__，覆盖过滤、事务边界、认证、幂等、记忆失败与重复同步。
浏览器测试位于 e2e/onboarding.spec.ts，使用模拟认证与接口，不读写现有用户画像。
截图位于 .screenshots/onboarding。

本期不实现：
- 普通聊天、学习辅导、旧画像对话的统一自动补全及冲突确认。
- 设置中心的画像表单编辑和双向联动。
- 画像完整版本快照、历史记忆重新校验与批量迁移。
- 行为统计推断学习频率、节奏；每日计划和日程自动生成。

旧画像对话组件保留为后续兼容代码，不再是默认引导。本期没有把它作为新的编辑入口。
